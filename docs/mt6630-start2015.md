# MT6630 client2015 / provider1024

基点combo1023 source701182c1とclient2014 source338e2b58。実Code10（既ROOT\SYSTEM\0001、root1/child0/radio21）の失敗APIは未確定。Kernel-PnP219 C000025EはAPIを特定しない。2014の任意HFP通知登録を実OPENとphysical owner取得後へ移す修正を保持する。

旧QUERY_CAPABILITIESはbroker失敗/malformed reply/not-readyを成功None/0へ変換していた。2015は実NTSTATUSを返し、正規caps成功は実transport-bypass predicate成立時のみ。Microsoft BTHX GET/SET_VERSION・command/ACL/event型1/2/4・packed context offset5を保持。架空SCO/PCM/latency/drainやACL-only成功は追加しない。

provider1024は単一NDIS worker上の既OPENから64B receiptを生成し、同file・同generation・OPEN return後にprivate kernel IOCTL0x949で返す。admission/NVRAM/STP attach/WMT function/FC1A/FC72/FC79/FC93/FC7A/FC22/ReadVersion/ReadBD_ADDR照合のenter/return/success maskと実backend code/NTSTATUSを保存。末尾4wordは開始時の実FILETIME low/highとinterrupttime low/high。MAC/BD_ADDR/NVRAM/payloadは出さない。command列/値/FW/MMIO/共有電源/NDIS構造layout/WiFi RXretry・assoccapsは変更0。記録のためにOPENやI/Oを再実行しない。

clientは選択class key\MT6630StartCheckpoint\BrokerOpenV1へ保存し、ReachedMask bit16/BrokerReceiptは取得status。bit11 BrokerHciOpen/bit13 D0Return/bit15 Capabilitiesと分離し、同bootで未到達の旧値を現成功にしない。Driver ParametersのDriverCreated/AddEntered/DeviceCreateStatusも記録する。ログ失敗は実PnP/OPEN結果を変更しない。

一次sourceはCT3 stp_chrdev_bt.c BT_openのfunction-on→STP-ready、Linux本機a04br3_mt6630_bt.cの正規HCI setup、既XNU由来WMT/STP channel。stock FC72先頭0x63 packet ruleと動的NVRAM read/readback比較を保持。保存NVRAMのproduction parser host再生はformat検証だけで、Windows実disk API/STP/HCI成功証拠ではない。公開WDF sourceのnon-PnP target正規化から『CDOだから必ずopen失敗』は採らない。RT81 WDFのREA検索は関数未解決で実binary契約未確定。

増分はprovider2TU/実1023の41objects再利用、client1TU/2014 controller＋hfp_target/radio_bindingの3objects再利用。全再利用source/header/object hashを照合。親/Audio/GPU159/345/媒体変更0、root登録再実行0、既runner小closureのみ・SDK再setup0。

次通常batchはmain判断。実selected INF/SYS→class-key checkpoint→同boot BrokerOpenV1→D0/Capabilities→HCIchild/radioを区別し、最初の実失敗statusを次修正根拠にする。物理AP/付属機器/ユーザー操作不要。ビルド/署名成功とCode10解消/標準stack/RF成功は別である。

## 次通常postへの読取helper

read-mt6630-start-checkpoint.ps1は既read-only native clone内だけでdot-sourceして使う。既OfflineSystemHiveNative.csをロード済み・既root取得中にRead-Mt6630StartCheckpoint -Root $rootを呼ぶ。cloneを新しくloadせず、live HKLM/SYSTEMは受理しない。固定ROOT\SYSTEM\0001→選択System class→MT6630StartCheckpointとService Parametersの既知値のみをbounded readする。BrokerOpenV1の64B ABI/mask/flag/時刻をdecodeし、selected INF/DriverVersion、ReachedMask、同boot ModuleIdentity等との照合を呼出側へ要求する。失敗時は例外を既post receiptへ保存する。根因やHCI成功を自動合成しない。helper追加はtoolingのみで、署名driverのbinary source commitとは分けて固定する。
