## mainが既VM42796448681で実行（未実行）

入力ZIPを新規TaskRootへ展開し、正式repoのこのbranchの固定HEADを別worktreeに置く。例の`$src`はその専用worktree、`$task`はZIP展開先。C#等のLFを維持するためclone/fetch用repoはcore.autocrlf=falseを使う。ツールの実在・hashは本担当がVM照会したものではない。mainが既存の信頼したtool inventoryと照合して指定し、不足してもSDK setupやdriver再buildへ進まない。

```powershell
$src = 'C:\mt8167-usb1121-helper\source'
$task = 'C:\mt8167-usb1121-helper'
$Csc = "$env:WINDIR\Microsoft.NET\Framework\v4.0.30319\csc.exe"
$SignTool = '<mainが既存GPU367署名でも使用したsigntool.exeの実path>'
$CscHash = (Get-FileHash $Csc -Algorithm SHA256).Hash.ToLowerInvariant()
$SignHash = (Get-FileHash $SignTool -Algorithm SHA256).Hash.ToLowerInvariant()
& "$src\tools\ci\invoke-usb1121-helper-fixed.ps1" -BundleDirectory "$task\install-bundle" -Csc $Csc -ExpectedCscSha256 $CscHash -SignTool $SignTool -ExpectedSignToolSha256 $SignHash -OutputDirectory "$src\out\helper-signed" -BuildAndSign
if (!$?) { throw 'USB helper build/sign failed' }
```

BuildAndSignなしなら計画だけで、DLLや導入用helper-manifestを作らない。実buildは元90e recipeの`csc /nologo /target:library /platform:arm /optimize+`を一度呼び、既存BCBFでDLLを署名する。driver/SDK/PCO/UMDのbuild、VMのPnP APIやinstallerの実行はしない。

wrapperは入力bundle/source hash、Csc/SignToolの指定hash、署名trust/BCBF identity、ARMNT/PE32のCLR directoryを静的に確認する。ARM DLLをbuild VMでロードしない。既存installerが読む`MT8167_USB_ABI3_PNP_HELPER_V1` schemaを維持し、90e sourceと実wrapper commit、install plan SHA、tool/framework出自を追記する。

回収対象は`out/helper-signed/usb1121-helper-signed.zip`、`helper-manifest.json`、`build-receipt.json`。manifest SHAとDLL SHAはWindowsでの実生成後に確定する。ここでは値を作らない。

stage／DIF／親PnP／Resume／Rollbackはmainの後続USB transaction。GPU367/run197とは別工程で、このwrapperはそのどれも呼ばない。通常PC接続でUSBPORT20が不在でも、source ON／強制host／架空PDOで進めない。給電改善と実Windows ARM helper動作は未確認。
