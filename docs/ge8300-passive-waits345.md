# GE8300 345：PASSIVEのファームウェア同期待ち

157の同boot新記録は最初のClear入口（R15 op1/magenta）、境界NONEのR34、GPU firmware start成功のR37 phase1まで。windows_fence(dm0)後のphase2、Clear prepare後R38、Patch return R22は今回の値がなく、最初のClearより前のFW同期待ちが戻っていない。過去bootのR22/R35/R38等を根拠にしない。PC1点のReadTimeStampCounterだけを原因の証明には使わない。

Windows commandのFW ackポーリングはPASSIVE_LEVELであり、KeStallExecutionProcessor10usを最大10000回呼んでいた。345はKeDelayExecutionThreadで1msを要求し最大100回へ変更する。実同期ワードとCCBの比較、poison状態、失敗NTSTATUSは維持する。要求待機の合計は100msだがWindowsのタイマー粒度やスケジューリングで壁時計時間が増える。成功をタイムアウトへ置換したり失敗を成功へ変換しない。

同じPASSIVE退役処理のIRQ drainもビジーウェイトを1msのKernelMode非alertable待機へ変更し、KeQueryInterruptTimeによる既1秒budgetと最大1000回の上限を設ける。GPUレジスター、CCB、shader、PTE、IRQ所有権や正常retirement proofは変更しない。短いハードウェア初期化用delayやDIRQL submitには待機を追加しない。

Windows kernelの待機APIを用いた本修正候補であり、実機同期完了・2色の画素・Draw/texture・長期安定は未検証。344の同boot処理段階記録を維持して一括評価する。
