# DWM resource geometry and partial updates

This branch is based on actual GPU368 source a04e22489709db79d7c5a4355419bc7aaf95b057. It does not change the timing369 package, firmware, boot image or deployment profile. Hardware and DWM operation are unverified. Premultiplied alpha blending is implemented in source for BGRA8 ONE/INV_SRC_ALPHA ADD on RGB and alpha. Other factors/operations, logic operations and partial channel masks remain rejected. This is not a hardware-qualified Windows GPU driver.

Offscreen BGRA8 RT and RT/SRV allocations now retain descriptor width/height. Their pitch is rounded to 128 bytes, as required by the source PBE producer's 32-pixel stride. The producer admits edges up to 4096, at most 4096000 storage bytes (the existing 1000-page private output capacity). The actual tile/TPC allocator independently enforces its data window. Examples include 1280x800/pitch5120 and 801x600/pitch3328. Increasing an admission constant cannot bypass MDL extent, page-table identity, alias, aperture or cold storage checks. Physical primary/scanout remains 800x1280/pitch3200.

A target change uses the existing completed-boundary/stop/retire/cold-rebuild sequence. Geometry and pitch flow into HWRT, PBE, PPP region clip, output extent, viewport and background texture descriptors. Merge lower/upper/scale use the vendor binary32 operation sequence with integer round-to-nearest-even arithmetic, with no kernel FP or new ARM divide-runtime dependency. Viewport admission checks the captured target dimensions. Integral viewport coordinates and depth [0,1] remain the implemented subset.

D3D11.1 ResourceCopyRegion and backend Blt capture an integer, non-scaling RT-to-staging rectangle. Source and destination dimensions/pitches are independent. The kernel snapshots the packet through MmCopyMemory into nonpaged storage, checks both logical extents, and retains both opened allocation references on its normal DMA ticket. Native TQ uses the source-generated region USC and real mapped MDLs. It changes source coordinates and destination clip, never substitutes CPU pixels or a synthetic completion. Destination changes require hardware-off retirement before any new graph/PTE publication. Unsupported formats, scaling, mips, samples and CopyFlags are rejected. Ordinary staging-to-staging RAM copies remain explicit RAM copies.

`tools/ci/test-ge8300-dwm-contracts.py --output <host-output>` checks production wire/native producers with ASan/UBSan. It covers 937 layouts against a host float oracle, independent-copy pitches, shortened extents, rotated/non-aligned draw targets and immutable-output failure. Existing residency checks cover reference retention until the real completion path. These tests do not prove hardware raster output.

The hardware field sources are the existing Imagination native producers and Mesa `rogue/ppp.xml`, `rogue/pbestate.xml`, `pvr_arch_job_render.c`, and `pvr_uscgen_tq_frag_coords`. The merge sequence preserves the existing board-source constants rather than deriving timing from geometry. Timing handoff and GPU clocks are unrelated to these offscreen allocation dimensions.

A Windows build must recompile every native/KMD/UMD TU depending on changed internal headers from this fixed branch. Mesa core source/API and codegen flags are unchanged. The 375-TU bundle also contains 10 Windows adapter TUs; changed adapters must be compiled again, with original core objects retained only after strict live checks. Do not reuse a04 driver objects solely because a TU's own .c file is unchanged. SDK setup/rebuild and PCO375 recompilation are unnecessary. No Windows signed package is produced by this source-only work.


## Premultiplied alpha

The shader-state cache retains a separate immutable variant for the exact supported mode; its key is the parent's actual tokens/signatures plus that mode. Texture and general arithmetic PS variants use the same production compiler entry points as opaque shaders. COLOR pair compilation uses the same linked IO producer. Source inputs are clamped before normalized-format blending, following Mesa `nir_lower_blend.c`; BGRA PIXOUT is read with OLCHK, unpacked, blended and packed. General shader witnesses permit only a bounded scalar PIXOUT0 read with OLCHK, and UNPCK.U8888 with validated register/repeat bounds. A non-fetch shader contract cannot read PIXOUT. No memory/branch/indirect opcode is newly admitted.

Mesa `pvr_arch_pipeline.c` selects TRANSLUCENT for `fs.uses.fbfetch`; `rogue/ppp.xml` encodes that in STATE_ISPA bits24..26, distinct from ISPCTL upass. The native job couples that pass to the selected blend variant. Its existing source-generated background load reloads the actual RT before fragment operations; existing cold graph, real fence, SLC/CPU handoff and MDL lifetime continue to apply. Clear is not substituted for a blend or preserved background.

The production compiler -> witness -> native producer contract test covers general/Texture2D/COLOR variants, rotated descriptor geometry, scissor, correct pass selection and rejection of an incorrect opaque state. Local ARM compilation of changed runtime consumers uses saved WDK inputs; formal Windows compilation/link/sign and pixel output remain unverified. The host check explicitly pins the existing ROA PCO reference link manifest and each linked object; it does not silently use the stale generic host PCO archive. This host reference does not replace the recovered Windows375 strict cache or claim that Windows variant codegen was executed.

## Build without SDK/PCO reconstruction

Use `tools/ci/build-ge8300-dwm-source.ps1` with `-VerifiedCompilerDirectory <recovered-fixed198-compiler> -ExpectedCompilerCacheManifestSha256 <actual-link-manifest-SHA> -VcToolsDirectory <existing-14.44> -KernelVcToolsDirectory <existing-14.29> -WindowsKit10Version 10.0.22621.0 -OutputDirectory <new-checkout-local-output>`. All arguments are real existing inputs, not guessed VM paths or a fabricated cache SHA. The wrapper has no cold-compiler fallback, performs no SDK setup, and produces unsigned outputs. The Mesa365 source/API closure and all 375 unit flags/routes are unchanged; the adapter source-plan hashes change. The changed owner, shader metadata and resource headers require dependent native/KMD/UMD object recompilation. Where the old driver include evidence is incomplete, this recipe rebuilds the dependent driver set conservatively instead of asserting old-object equivalence. For a finer dependency plan the existing `plan-ge8300-incremental-runtime.py` can consume actual old include/tool records; missing records must not be populated from current source.

This branch starts at a04/GPU368 and deliberately excludes the GPU369 timing consumer changes. Integrate that source in an independent candidate before any later combined build; do not replace the timing369 signed package or boot image with outputs of this source-only recipe.


## Derive the changed adapter objects without rebuilding Mesa365

The old full375 cache is not byte-identical to this branch's adapters. Keep the old cache unchanged. First run `python -B tools/ci/derive-ge8300-adapter-cache.py --baseline-source <clean-actual-a04-compiled-checkout> --cache <recovered-original-cache> --expected-link-sha256 <original-link-manifest-SHA> --vc-include <existing-14.44/include> --ucrt-include <existing-22621/ucrt> --sdk-shared <existing-8.1/shared> --sdk-um <existing-8.1/um> --vc-arm-libraries <existing-14.44/lib/arm> --sdk-arm-libraries <existing-8.1/Lib/winv6.3/um/arm> --ucrt-arm-libraries <existing-22621/ucrt/arm> --output <new-checkout-local-derived-cache>`. No VM paths or hashes are assumed.

The helper verifies the original strict375 cache against its actual clean compiled source and current tool/API inputs. It then resolves current includes, retaining only objects whose source/flags/include closure exactly matches the original recorded evidence. Changes to a Mesa-core TU stop derivation; only Windows adapter TUs can be recompiled. Original .d/.log files and parent evidence are retained unchanged; new adapters obtain real new compile results/traces. Only archives containing rebuilt objects are re-archived. Output metadata identifies each actual compile source commit and records the original parent hashes. No unknown historical hash/exit is filled from today's files.

Use the resulting link-manifest SHA and cache with `build-ge8300-dwm-source.ps1 -AllowAdapterDerivedCompilerCache ...`. Derived evidence uses an explicit opt-in schema. The normal strict cache/default CLI and cold build are retained; an old cache is not relabelled as wholly recompiled. These Windows commands are prepared in source and have not been executed here. SDK/core compiler recompiles remain zero.
