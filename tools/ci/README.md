# Windows ActionsのSSH介入

DMA待機中の詳細UART出力は既定で無効です。調査時だけ `A04_DMA_PROBE=1 A04_DMA_POLL_TRACE=1` を指定して有効化できます。失敗時の診断出力は引き続き有効です。出力の有無による転送時間と安定性の差は実機で確認する必要があります。

`A04_PASSIVE_IO=1` は、Storportワークアイテムの読取り専用WinPE診断です。書込み機能とブート用パッケージとの組合せはビルド時に拒否します。要求取消し・アダプター削除時の安全性と実機動作は未検証です。通常OSに登録しないでください。

例外の `A04_SCRATCH_IO=1` は、明示した `A04_SCRATCH_LBA` の8セクターにだけ書き込める、一時WinPE専用の診断です。passive・DMA・仮想実験経路・書込み有効を必要とし、ブート用INFとの組合せは拒否します。ドライバは実機GPTのCRCと全領域を検証し、指定範囲が使用可能領域内かつ全パーティションと重ならない場合のみ書込みを許可します。未割当は空データを意味しません。ホストは実機から事前に8セクターを退避してSHA-256を記録し、その4 KiBを一時WinPEの `X:\a04br3\scratch-original.bin` に入れます。診断プログラムは実機の内容と事前退避が一致しない場合は書きません。成功・失敗・ハングのいずれでもホストがRecoveryから事前退避データを復元してください。端末固有の退避データを配布イメージへ含めないでください。仮想miniportによる実機MMIOは非サポートの実験であり、本体OSへ導入しません。

`A04_SERIAL_QUEUE_EXPERIMENT=1` は診断構成でStorportの最大同時要求数とLUNキュー深度を1にします。`A04_ISOLATED_REQUEST_EXPERIMENT=1` は非同期処理用にSRBとデータを複製し、StartIoロックで元要求の完了とバスリセット時の切離しを同期します。両方とも明示的なscratch診断または下記のboot試験に限定され、既定では無効です。バスリセットは元要求をBUS_RESETで返した後もFALSEを返し、ハードウェアのリセット成功を主張しません。`A04_ISOLATED_RESET_TEST=1` は特定の読取りをワーカーで2秒待たせて保留中のリセットを試す追加診断です。実行中DMAの停止、アダプター削除時のワーカー寿命、再初期化、電源復帰、要求順序は未解決であり、本体OSへの適用はできません。

`A04_BOOT_PASSIVE_EXPERIMENT=1` は、上記の単一キュー・分離要求を、GPTで検証したWindows領域とESPのみへ書き込むboot-start INFの実験構成につなぎます。passive・DMA・仮想実験経路・書込み・boot・単一キュー・分離要求をすべて明示し、scratchや強制待機リセット試験と併用できません。既定では無効です。実機のWindows領域全体を退避・照合し、旧ドライバと元ESPへの自動復元経路を用意した研究用試験だけに使用してください。上記のDMA停止・PnP・再初期化・電源復帰・順序の未解決は残り、製品ドライバではありません。

`Windows 8.1 WDK availability` を `ssh_debug=true` で手動実行すると、SDK/WDKの準備が成功または失敗した後、同じWindowsランナーを最大180分保持します。ジョブ全体の上限は210分です。終了時にランナーと変更内容は失われるため、必要な修正はリポジトリへ反映しpushしてください。WDKのビルドが自動で成功することを意味しません。

GitHub CLIでリポジトリに認証し、実行IDを確認した上で `python3 tools/ci/connect-runner.py <実行ID>` を実行します。接続に使う秘密鍵は開発機のSSH agentまたは通常のSSH設定に置きます。リポジトリシークレット `A04BR3_RUNNER_SSH_PUBLIC_KEY` に公開鍵のみを登録する必要があります。ワークフロー起動者のGitHub公開鍵も許可されます。非対話コマンドはIDの後に指定できます。手動終了する場合、ランナーのチェックアウトに `end-ssh` ファイルを作成します。

接続情報とランナーの一時ホスト公開鍵は、その実行のGitHub Actions artifactから取得します。中継サービスのホスト鍵はリポジトリで固定し、ランナー自身のホスト鍵もartifactに照合します。公開中継 `ssh-j.com` を使うため、中継の可用性に依存し、接続先を外部に公開します。ランナーは公開鍵認証に限定します。公開リポジトリのActionsには機密データを置かず、信頼できる起動者・鍵のみを許可してください。`ssh_debug=false` が既定です。

大きなファイルは標準入力ではなく、同じホスト鍵照合を行う `python3 tools/ci/copy-runner.py RUN_ID upload LOCAL D:/path/file` または `download` でSFTP転送できます。ダウンロードは一時ファイルへ保存後に名前を確定します。転送元・転送先のハッシュは別途照合し、権利を確認して非公開の一時領域だけで扱ってください。

`Windows runner SSH smoke test` は同様の接続を6分間検証する専用ワークフローです。
