# run117：RT8.1シェーダー署名修正

run115後のcaptured-unmounted fresh116を明示結合する。GPUは実選択3.22から3.23へ更新し、parent1101、USB1009、MMA1.10、AJTD4R eMMC1.9、RTC1.0、thermal1.7と対応8range POST bootを保持する。RTC以外の新周辺機能の完成を意味しない。GPU更新に伴うUEFI/GPT書込みは行わない。

新UMDのsourceはeb4dca0e、署名package/helperは50974a3c。3f8291d0のUMD archiveをsourceから再構成した基点へtokenized_shader1TUの差分を適用しており、過去archiveの全byte一致とは区別する。KMD320/native322/FW/固定clientは3.22からbyte保持する。旧6TU manifestは旧clientの出自、新UMD manifestは今回DLLの出自としてそれぞれ検証する。

標準D3D11で2色Clear/readback、三角形、色補間を1clientでまとめて確認する。clientの再試行は0。既存Engine/旧GPUの履歴、Graphics設定、既存data directoryと新しいRun117 directoryを分離する。媒体生成、署名、実機shader成功、全GPU機能完成を区別する。

このprofileは固定のprivate captureと署名済み候補を要する実機更新用であり、一般配布用Windows媒体ではない。driverのsource buildはshader323-buildおよびsingle-checkoutの手順を参照する。

保持nodeのメタデータ観測では、CM status/problemを先行して独立記録する。DevicePropertyのDriverInfPath/DriverVersion/DriverDateがERROR_NOT_FOUNDの場合だけ、同じHWID/service/classへ一意に一致したdevnodeのSetupDiOpenDevRegKey(DIREG_DRV, KEY_QUERY_VALUE)からInfPath/DriverVersion/DriverDateDataを読む。型・サイズ・期待値の検査は維持し、元APIの値不一致・型不正・アクセス拒否は代替経路へ逃がさない。レジストリへの書込みはない。run115のどのAPIが490を返したかは未確定なので、この経路利用と元API結果を別eventで記録する。

MicrosoftのAPI契約: https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdiopendevregkey 。DIREG_DRVは対象deviceのsoftware keyを開く。native選択metadataも同じdriver class keyの値を読み、fresh116で各候補版・date・SYS hash一致を確認済み。API欠損を成功へ置換せず、同じ選択ドライバの別の公式読取り経路で固定値を検証する。

同じdiagnostic起動でthermal-firmware-readonly.hを一度呼び、既存UEFIの校正・PIO handoff変数をread-onlyでprivate新規logへ保存する。16/72byte取得、API/権限/復元/サイズの結果を区別し、取得失敗をGPU終了コードへ接続しない。FW変数への書込み・IOCTL試験は行わない。校正rawはprivate回収だけとし公開Git/Notion/Discordへ掲載しない。

SCM EXEのbuild helperはKitHeaderRoot/LibraryRoot/SigntoolPathを明示でき、既存header・ARM importlibs・署名toolを再利用する。既定値は従来のWDK8.1配置。今回の最小hostは8.1 headersとSDK10 17763 ARM importlibsで、各path/hashをservice manifestのtoolchainへ記録する。SDK10 libraryを8.1由来とは記載しない。要求APIはRT8.1の実exportへ照合する。
