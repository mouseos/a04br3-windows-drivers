# SD7: run49 child PDOの名前消失を修正

## 実失敗と一次sourceの対応

main回収run49の固定NativeCheckpointはschema1/revision4/sequence7、AddDevice stage28
(child WdfDeviceCreate)、statusC0000033(STATUS_OBJECT_NAME_INVALID)、complete1。
DriverEntry stage2/status0で、Prepare/D0はstage0のまま。カードinitやsupplier取得より前の失敗。
初回DIF E0000204とこのPDO生成失敗は別工程である。

Microsoft Windows-Driver-Frameworks固定source
`b6191d9543441329154da32f7ab9bdd97228dd3c`で次の実経路を照合した:

| source path/開始行 | 対応する事実 |
| --- | --- |
| src/framework/shared/core/fxdeviceinitapi.cpp:1896 | WdfPdoInitAllocateがSetPdoを呼ぶ |
| src/framework/shared/core/km/fxdeviceinitkm.cpp:32 | SetPdoがFILE_AUTOGENERATED_DEVICE_NAMEをCharacteristicsへORする |
| src/framework/shared/core/fxdeviceinitapi.cpp:252 | SetCharacteristicsのTRUEはOR、FALSEは既存値を置換。SECURE_OPENは別途保持 |
| src/framework/shared/inc/private/common/fxdeviceinit.hpp:245 | HasNameは明示DeviceNameまたはAUTOGENERATED flagが必要 |
| src/framework/shared/core/km/fxdevicekm.cpp:243 | PDOでHasNameがFALSEならSTATUS_OBJECT_NAME_INVALIDを返す |

旧SdCreateChildはFILE_REMOVABLE_MEDIAをFALSEで設定して既定flagを消し、明示kernel名も
付けていなかった。修正は同APIの第三引数をTRUEへ変え、removableを既定値へ追加するだけ。
DEVICE_ID/instance IDはkernel object名の代替ではない。固定kernel名を作らず、frameworkの
正規自動命名を維持する。エラーを握り潰したり、PDO生成失敗を成功化しない。

## 候補と検証範囲

単一consumerの固定checkpointを保持し、その後続へこの根因修正を統合する。
[SINGLE-CONSUMER.md](SINGLE-CONSUMER.md) のCSQ/上限8/受付時deadline/cancel/rundown/
power契約は維持。親1010、eMMC、USB、WiFi、Audio、ACPIは非編集。

INF5/INF6は既に異なる固定sourceで署名済みのため、同版異SYSを避けて最終INF7へ上げる。
NativeCheckpointは同じ40byte/schema1、driver_revision=7。SD4署名候補も凍結。
Device/Timerの許可済みPassive指定は変更しない。

実測statusと一致するsource上の根因を修正したが、修正後のAdd成功、GenDisk列挙、
card init、READ/WRITEはmain実機の後続一括観測が必要。ここで実機成功とは扱わない。
同stageの細かい実機試験や大量mockは追加しない。
