# WDK8.1 ARMのカーネルリンク

このコンポーネントのKMDは、既存のMicrosoft C++ toolsのLINKでリンクする。UMD、Mesa/PCO、native ownerのコンパイルを変更する条件ではない。

Windows RT 8.1実機でDriverEntryとcontract検査の成功後、DxgkInitializeがSTATUS_OBJECT_PATH_SYNTAX_BAD (0xC000003B)を返した。REA/Ghidraによる同一3.4 SYSの解析では、displib.objのDlpGetServiceNameInSystemSpaceが、UTF16のDXGKrnlサービス名の先頭ではなく先頭+1を参照していた。生成されたliteral poolでも奇数アドレスを確認した。同一KMD archive/native ownerをMicrosoft LINK14.44で再リンクすると、この参照は文字列の先頭になった。実行領域内のデータ参照をThumb関数アドレスと区別する必要がある。これは観測した出力についての結論であり、LLDの全バージョンを評価したものではない。

解析対象SHA256は88909fbd30228c3de9a48a9ef8206a267848d9209d1373998073c05c16fce17f。REA Evidence: ev_af5436830a41a86e616382a359711b525217bb3bb656f56562a4bed85157498f、ev_b56a00d5e6cefc4a943e95993c18abc678b5af804fa58b05546b00ef36984f3a、ev_19030d00150cbe28f983d77140edf29db0790c15281194b7bba36a746fbb8d92、比較ev_6a9378f5b92a8cf3404f2603f8242a2bfb7a5addb0f6629fdb9b436e2251b787。静的な参照修正と、実機のGPU描画成功は別に検証する。

`link-kmd-msvc-wdk81.ps1`は既存Visual Studioをvswhereで検出し、追加インストールせずにARM/nativeリンクを行い、LINK本体・displib・生成SYSのhashとLINK版を保存する。通常ビルド入口もこの経路を使う。`build-msvc-update-wdk81.ps1`は検証済み3.4オブジェクトを再利用し、変更のないCソースをgitで確認してからリンク・SYS/CAT署名を行う。署名済みUMD、FW、compilerを保持する。
