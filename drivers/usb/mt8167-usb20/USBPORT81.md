# 実RT8.1 USBPORT miniportとroot hub

USB1011のhelperから独立したWDM miniport `usbport_hcd.c` を追加した。
`DriverEntry`が実USBPORTのGetHciMnを確認してRegisterUSBPortDriverを呼ぶ。
root hub PDOとそのPnP/USBDI処理はinbox USBPORTへ委ねる。
HCD1014では親のboard観測producerまで接続した。初回の実5V、過電流回路の実作動、標準hub起動と実機転送はmain確認まで未完了。
HID経路のSYS/INFを変更せず、別SYS/INFにしている。opt-in親はUSBPORT20という別devnodeを生成し、旧HID LowerFiltersを継承しない。

## 原本と解析の区別

実usbport.sys SHA256:
`c668b894e7733206f987d85296f5e2d5fb4cf5b06c12ee43ea5afef85d4c31fe`。
実usbehci.sys SHA256:
`958d78c56ed991a34d60d28457e0470c158d89646b9597dde600e06840d8b57c`。

原本REAが間接callbackの一部を関数認識しないため、解析用コピーに、
確認済みcallbackアドレスをPE entry/exportとして追加した。元の全section bytesは
変更していない。コピーの署名宣言は除去し、成果・配備用には使わない。
そのコピーのEvidenceは解析用コピーに対する静的観測であり、原本を実行した
観測ではない。再生成スクリプト、原本/コピーSHA、全section照合manifestは
プロジェクトのログ/成果物側に残す。ソースrepoへバイナリを持ち込まない。

公開ReactOSのusbmport.hは用語・契約候補の対照に参照したが、そのまま
RT81 ABIとしてコピーしていない。特に同公開宣言はRegisterの引数が3個だが、
実RT81は第4引数RegistryPathを消費する。実呼出し側で確認して4引数を定義した。

## HCD1014：board観測producerと単一親

基点は親1104+HP1107 ABIを含むGPIO19後段1108 source607a10d2。
旧1013親を丸ごと戻さず、この現行親へUSB差分だけを三者mergeし、RTC/HPの変更を保持した。
serviceは `MT8167MUSBHcd`、HCD版1014、独立親package1114。

`musb_parent.inc` のQuery/Acquire/Observe/SetVbus/StopAndProve/Releaseは実MMIOと
既存 `usb_owner`/PWRAP/pwrapLockへ接続した。NOT_SUPPORTED固定stubではない。
ABI2を使い、OCはGPIO21のactive-low入力をIES21..23実readback付きで観測する。
stock mt8167.dtsiはoc_gpio21/IDDIG41、a04br3.dtsはGPIO22 source/34 detectを定義。
Linux CONFIG_OCは無効であり、実OC保護回路の作動や電流閾値を観測したとは主張しない。
unknown biasへpullを足さず、foreign mux/outputを拒否する。OC low/invalidなら給電しない。

QueryはGPIO読取りだけで候補資格を返す。PC接続（ID41 highまたは外部detect34 low）は
副作用0で拒否する。親の500ms one-shot timer→PASSIVE workはhost-roleへの変化を
読取りで観測し、その時だけ新USBPORT20子PDOを列挙する。PC時に失敗devnodeを常設せず、
後からhost cableを挿すとPnPが標準HCDを開始できる経路。これは実機未検証。
役割喪失時はconsumerがsourceを停止し、lease解放後だけ子をMarkMissingし、
cleanup後に次のhost-roleを列挙する。D0終了はtimer取消し→work flush→親mutexでdrainする。

子PDOのPrepareHardwareが実raw/translated memory2件+IRQ1件を検証・保存し、
親producerはその実PnP割当だけをmapする。raw MAC11100000/PHY11110000、64KiB各、
exclusive、GSIV104/levelの既存契約を検証。identity mappingの合成は禁止。
Acquireは同世代・再観測→既存単一USB rail/clock/source lease→MAC/PHY map→
GPIO21 IES/readback→HWVERS安定read→独立PIO停止・非強制VBUS観測まで実行。
途中失敗はparent lease/mappingをretainし、unmapを拒否する。

既存PHY準備は6d=3eの強制信号を設定するため、そのままDEVCTL=18を「5V」とは扱わない。
consumerはPrepare/Runの後に同maskを解除し、producerもPHY6d&3e=0とMAC74のforce bit2=0を
毎回検査する。DEVCTL[4:3]=3は比較器のVBUS-valid帯域であり、5.000V測定値ではない。
GPIO22を上げた後、OC/role/error/非強制statusを検査しながら比較器validを5連続観測する。
最大100msで未収束・OC low・role loss・VBUSERRORならsourceを落としてfaultにする。
初回の実5Vはmainの実機確認まで未完了。

StopAndProveはconsumerの停止申告に依存せず、親の別mappingからsource OFF、
DMA8channel/QMU非稼働、IRQ mask、16 endpointのFIFO/REQ停止、SESSION offを確認する。
未知active DMA/QMUにはcontrol/address/resetを書かず失敗・retain。
停止が実証できない時は成功を返さず、driver-owned shadowも既存consumerが保持する。
source latch OFFとconnector comparator OFFを分離し、PCから外部電圧がある場合に0Vを捏造しない。
同世代stop証明と再確認が成立した時だけRelease/unmap。
全power/GPIO/clockは同一pwrapLock下の既存usb_ownerを使い、standard profileのv1 acquire/vbus/health/releaseを拒否する。
Observeはsource稼働中のrole/OC/VBUS異常でGPIO22をOFFにする。PHY校正/SESSIONの待機間もconsumerが
Observeを呼ぶため、待機中に資格の監視を止めない。親D0終了ではGPIO遮断のみを行い、controller MMIOの
停止はconsumer worker rundown後のStopAndProveに限定する。retained leaseがあればD0ExitはBUSY。

1013の16KiB shadow、cookie/ticket/epoch、5秒deadline/100ms proof鮮度、USBPORT-owned
async poll、Abort/Close/Stop detach/rundownを保持する。明示0xE2/fastfailは追加していない。

## 実RT81の非同期通知契約

USBPORTの `invalidate_endpoint` は実binaryでsignature確認後にreturnするだけだった
（ev_a0be19b3698397edbb689e5052b88b1bdb1b88d12fcc171d8d016fce8df4bef2、
asm ev_571645a591734e73c277e684a7c963798095e17fe9a6fadd65f107930b0fc60f）。
これをworkerの完了通知として推測使用しない。

legacy async slot+0x10cは実Registerが0x3b901を設定し、
`(miniport, delay_ms, payload, payload_bytes, callback)` を0x25c7cへ渡す。
payloadは同期コピーされ、callbackは `(miniport, copied_payload)` でDISPATCH呼出し。
取消し時にもcallbackが呼ばれるのでstarted/epochを毎回照合する。
根拠: ev_f0321ea744103669cfc0dfe9536cc1c100946fd8a486bd817ade7e13724ed477、
ev_e487f20b3893a2d4af234025d7b57327f9783c599c25fe3191bfcc4effdacdbf、
ev_b6778e7a05f14c9a6b28f8a0704d7b3ddb753ec6fbaa72ed95e64b75341fb985。
停止中のasync取消し呼出しもev_f5d84968b1ac69bc911dbf8f727a578e7b35fd6cf1b0cdc3ebaaa3e819320dd8で確認。

invalidate_controller slot+0x118の理由3は実0x1fa64→0x1fa90→0x26435で
疑似割込みDPCをqueueする。理由0はno-opであり使用しない。
根拠: ev_b5435fd8ff6c02bf8058cd65653ea98137679da0cb9d3f458a6ae5b053da8884、
ev_cf6e73d6af1b89b3c7631f79f51bb5849814b81dc78102accc07b425883632bf、
ev_7305222a039459f5ad8d5e2de4a9fa9c0400fe6da41573933b98c9ad5741efc7。
10ms async通知はこの経路でUSBPORT自身にpollを要求する。
workerがOSの拡張寿命へ勝手に参照を伸ばす設計にはしない。

PollControllerは実0x13858がFDO+0xd54 spinlock内、PollEndpointは実0x15650のevent0xeが
FDO+0xd50 spinlock内で呼ぶ。ev_c82ebb5a6e5dc78d0b97930b31dac212a28dc644cc6b4938a364bbd67d03f96a、
ev_29f0b21d6af389d62a5c1a6e75eb951d7cc2095a1a6aa54c2ae03b404deaee1f。
0x13904は疑似割込みを通常の転送DPCへ渡し、0x1f934が0x15079を転送DPC処理として登録、
0x15078がevent0xeを経由してPollEndpointへ到達する。生ポインタをPollControllerから持ち出さない。
これらは静的解析であり、実RT81上での登録・実行成功を観測した証拠ではない。

## 親側のopt-in

`A04_SHARED_USBPORT_CHILD=1` は既定オフ。opt-in時だけUSBPORT20子PDOを生成し、USBPORTの
IOCTL_ACPI_GET_DEVICE_INFORMATIONに対する合成bus自身の識別情報を追加する。
firmware ACPIの観測結果を装わず、silicon revisionも報告しない。
実際の親busのGUID_BUS_INTERFACE_STANDARDを転送する。DMA/translateメソッドを
捏造しない。WDFのQueryCapabilitiesは既存実装を使用する。
owner ABI2はopt-in子から親へ転送する。GPIO21 OC観測・unforced DEVCTL比較器・実割当・
確定PIO停止のproducerを実装済み。電気的5V値・OC保護回路の定格/実作動は未確認。

現main親や媒体をこのbranchの古い親で巻き戻さず、mainの新しい親sourceへこの差分を
合流してから固定manifest付きで再ビルドする必要がある。

## 検証と未達

`make test-mt8167-musb-owner test-mt8167-usb-faults` がproduction PIOをASan/UBSanで実行する。
`tools/ci/build-mt8167-usbport-hcd-incremental.ps1` は既存WDK81 cacheで
10TU ARM compile/link、実WDK型x64 callback/物理backend合成試験、opt-in親TU compile、SYS/CAT署名を行う。
親TUはcompileだけで、現親の置換・配備をしていない。

consumer/親producerを実装済み。実機上の電気的資格、標準hubへの実binding、実RT81登録成功、PnP start/stop、
control/汎用転送の実機成功は未確認。回収manifestはこれらをfalseのまま記録する。

実RT81媒体のWindows/inf/usbport.infでROOT_HUB20→ROOTHUB.Dev→usbhubサービス、ServiceBinary=usbhub.sysを確認した。usb.infのStandardHub.Devも同じセクションを参照する。root ID生成だけで標準hub起動成功とは扱わない。
